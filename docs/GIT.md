# Git 워크플로

커밋·푸시·병합을 하기 직전에만 읽는다. 개인용 저장소이며 공개 가능한 상태다(공개 전환 자체는 사용자 결정). Claude는 아래 규칙에 따라 **스스로 커밋·푸시하고, 조건이 맞으면 병합까지 한다.** 사용자에게 매번 묻지 않는다.

## 브랜치

- `main`은 항상 테스트 통과 상태를 유지한다. 기능·리팩터 작업을 `main`에 직접 커밋하지 않는다.
- 작업마다 브랜치 하나: `fix/<슬러그>`, `docs/<슬러그>`, `chore/<슬러그>`, `feat/<슬러그>`.
- 여러 대화방이 병렬로 작업하면 각자 자기 브랜치만 쓴다. 남의 브랜치는 건드리지 않는다. `main`이 갱신되면 자기 브랜치에 `main`을 병합해 따라간다.
- 사용자가 "바로 고쳐"처럼 사소한 즉시 수정을 요청하면 `main` 직접 커밋을 허용한다.

## 커밋

- 논리 단위로 나눈다. 한 단계는 보통 여러 커밋이다. 관련 없는 변경을 한 커밋에 섞지 않는다.
- 모든 커밋은 `npm test`, `npm run repo:check`, `git diff --check` 통과 상태여야 한다. 통과하지 않으면 커밋하지 않는다.
- 메시지는 한국어, 기존 스타일(명사구 요약)에 맞춘다. 필요할 때만 본문을 붙인다.
- 커밋 메시지에 AI 생성 표식이나 co-author 트레일러(`🤖 Generated with Claude Code`, `Co-Authored-By: Claude …`)를 넣지 않는다. `.githooks/commit-msg` 훅이 이런 줄을 실제로 제거한다(`core.hooksPath=.githooks`, `npm install` 시 자동 설정). `.claude/settings.json` 의 `attribution` 도 비워 둔다.
- `data/`, `.local/`, 세션·토큰·쿠키·대화 본문·개인 절대경로는 절대 커밋하지 않는다. `repo:check`가 막지만 스스로도 `git status --ignored`로 확인한다.

## 푸시

- 의미 있는 커밋을 만들거나 작업 세션을 마칠 때 자기 브랜치를 푸시한다. 진행 상황이 원격에 보이도록 한다.
- `main`과 공유 브랜치에 force-push 금지, 히스토리 재작성 금지. 지금까지 사용자 승인 아래 두 번 수행했다.
  - 2026-08-30: `state.json` 히스토리 세탁([PRIVACY.md](PRIVACY.md) 1절)
  - 2026-09-12: 공개 전 커밋 정리 — 전체 히스토리를 의미 단위 4개로 압축([PRIVACY.md](PRIVACY.md) 1절)
- **이후 추가 히스토리 재작성은 하지 않는다.** 사용자가 명시적으로 다시 허용하지 않는 한 제안도 하지 않는다. 커밋 수를 줄이려면 PR squash 병합을 쓴다.

## PR과 병합

- 작업이 끝나면 PR을 연다.
- **PR 본문은 짧게 쓴다.** 훑어봐도 무엇이 왜 바뀌었는지 알 수 있어야 한다. 골격은 네 부분이다: 무엇을·왜(2~3줄), 바뀐 동작(필요하면 표 하나), 검증 결과 한 줄, 병합 보류 사유(해당할 때). 제목도 한 줄 요약으로 끝낸다.
- PR에 넣지 않는 것: 진단·재현 과정, 코드 인용, 파일별 변경 나열, 커밋 메시지·주석·테스트 이름에 이미 있는 내용.
- CI(`Verify / test`, macOS·Windows)가 green이면 squash 병합한다. Claude가 스스로 병합한다.
- 다음 중 하나면 병합하지 말고 PR만 남긴 뒤 사용자에게 알린다: 대량 삭제·파일 이동이 핵심인 변경, 인증·보안·`repo-check.js` 관련 변경, 실제 ChatGPT 원격 동작에 영향을 주는 변경, 사용자가 먼저 검토하겠다고 밝힌 경우.
- 병합 후: 원격·로컬 브랜치 삭제, `git switch main && git pull --ff-only`.

## 하지 않는 것

- 사용자의 명시적 요청·승인 없이 실제 ChatGPT 원격 변경을 실행하거나 그 결과를 커밋한다.
- **저장소를 공개로 전환한다.** 점검이 끝나도 사용자가 명시적으로 요청할 때만 `gh repo edit --visibility public`을 실행한다. 제안은 할 수 있다.
- 다른 프로젝트의 코드를 복사해 넣는다. `API_COMPATIBILITY.md`가 참고로 연결한 저장소들도 마찬가지다 — 계약을 확인하는 데만 쓰고 코드를 가져오지 않는다.
- 되돌리기 어려운 Git 작업(브랜치 강제 삭제, 태그 삭제, reset --hard on shared refs)을 사용자 확인 없이 한다.
