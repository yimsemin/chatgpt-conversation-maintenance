# 화면과 작업 흐름 설계

이 도구의 화면·세션·작업 구조가 지키는 원칙과 수용 기준이다. 목적은 [GOALS.md](GOALS.md), 구조는 [ARCHITECTURE.md](ARCHITECTURE.md), 반복된 함정은 [PITFALLS.md](PITFALLS.md)에 있다.

결정: 연결은 북마클릿(끊기면 자동 복구) · 사용 패턴은 조사 범위를 골라 필요할 때 정리 · AI 분류는 대화창의 에이전트가 하되 인계를 간소화.

## 사용자 여정 기준 목표 (수용 기준)

단계는 시스템 층이 아니라 **사용자가 겪는 순간**으로 평가한다.

| 순간 | 목표 |
| --- | --- |
| 화면을 열었다 | 3초 안에 연결 상태(끊겼다면 이유), 조사 범위 선택, 삭제후보 현황, 마지막 정리 결과가 보인다 |
| 정리를 시작한다 | 범위를 고르고 버튼 1번. 남은 시간이 즉시 보이고 범위가 작을수록 빨리 끝난다(특정 프로젝트는 그 프로젝트만 읽는다) |
| 기다린다 | 화면을 닫아도 작업이 계속되고 다시 열면 복원된다. 429·무응답은 이유와 자동 재개 시각이 보인다 |
| 검토한다 | 전체 표 없이 요약 한 화면 + 예외 목록. 적용 전에 "무엇이 바뀌는가"를 안다 |
| 적용한다 | 버튼 1번. 내부 한도·해시·계획 파일이 보이지 않는다 |
| 끝났다 | 바뀐 것과 직접 할 일(비게 된 프로젝트 이름, 수동 제거 대화, 삭제 표시만 한 대화), 제목을 바꾼 대화의 목록 순서 확인이 결과 화면에 있다 |

## 설계 원칙

- 사용자에게 내부 한도·해시·계획 파일 이름을 노출하지 않는다. 오류는 "무슨 일이 있었고 지금 무엇을 하면 되는지"로 쓴다.
- 작업 상태는 파일이 정본이다(`runs/<id>/`, `data/jobs/*.jsonl`). 화면·서버가 죽어도 이어 간다.
- **지난 상태를 기록해 두지 않는다.** 고른 범위를 그때그때 읽고, 안전은 적용하면서 대화별로 다시 읽는 검증(영수증)과 실행 기록이 맡는다. 일부만 읽은 범위의 결과는 읽지 않은 것(프로젝트별 대화 수 등)을 지어내지 않는다.
- 원격 변경 승인 규칙(명시 승인·확인 문구·잠금·재조회 검증)은 유지한다. 승인 흐름 밖에서 원격 변경 op를 실행하는 경로를 두지 않는다.
- 코드는 AI를 호출하지 않는다. 에이전트 인계는 파일 계약으로 한다.
- 삭제는 기본이 아니다. 삭제 후보는 삭제후보 프로젝트로 옮기고 영구 삭제는 고급 옵션이다.
- 안전 경계(원격 op 계약, 릴레이, 잠금, 영수증·재조회, 평평한 루트 모듈)는 그대로 둔다.

## 구현 메모

- 작업 상태 영속은 `data/jobs/*.jsonl`(작업 단위)이다. 서버가 죽으면 다음 조회에서 "중단됨"으로 닫는다.
- `GET /maintenance/session`이 현재 실행 포인터·작업·연결 상태·삭제후보 현황·알려진 프로젝트를 합쳐 단계(확인·제안·검토·적용·결과, 삭제후보 확인)를 계산한다(`session.js`). 실행 포인터(`.local/maintenance-web.json`)와 `phase` 문자열이 그 뒤에 있다.
- 프로젝트 목록은 꼭 필요할 때만 읽는다. 프로젝트 없는 대화 범위는 대화 목록(기간 14일·30일·전체)만 읽고 옮길 후보는 `known-projects.json`을 쓴다. 프로젝트 범위는 그 프로젝트의 대화 목록을 직접 읽는다(전체 목록이 프로젝트 대화를 빠뜨리기 때문, `API_COMPATIBILITY.md`).
- 읽기 간격은 429 이력에 맞춰 조절되고, 429 쿨다운 종료 시각은 공유 pacer가 들고 있어 서버가 떠 있는 동안 다음 작업이 이어받는다(서버를 다시 켜면 초기화).
- `overhaul.js`는 일반 명령으로 흡수하지 않고 카드·조각·조립 도구로 유지한다.

## 남은 결정

- 수용 기준(3초 안에 상태 표시 등)의 실측은 아직 하지 않았다. 범위 한 바퀴는 실계정에서 돌렸다(2026-09-26).
- 실행 포인터·`phase` 문자열을 세션 상태 하나로 합칠지는 그 실측 뒤에 정한다.
- 북마클릿의 탭 가시성 보고와 프로젝트 지도 화면은 필요해질 때 만든다(북마클릿 재설치가 필요하다).
