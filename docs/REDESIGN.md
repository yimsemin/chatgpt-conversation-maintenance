# 개편 설계 (정기 정리 중심)

전수 재정비([OVERHAUL.md](OVERHAUL.md))를 겪으며 드러난 문제를 고쳐, 이 도구를 **정기적으로 새 대화만 정리하는 도구**로 만든 설계다. 목적은 [GOALS.md](GOALS.md). 구현은 끝났다(2026-09-25). 구조는 [ARCHITECTURE.md](ARCHITECTURE.md), 반복된 함정은 [PITFALLS.md](PITFALLS.md)에 있다.

> **2026-09-26 방향 전환**: 평상시 운영을 "범위 선택 조사 + 삭제예정 프로젝트 이동"으로 바꿨다(일부 구현). 결정과 실측은 [GOALS.md](GOALS.md)의 "운영 방향 전환"에 있으며, 이 문서는 구현이 바뀔 때까지 현재 동작의 기준이다.

확정한 결정: 연결은 북마클릿 유지 + 자동 복구 · 사용 패턴은 정기 정리 · AI 분류는 대화창의 에이전트가 하되 인계를 간소화.

## 사용자 여정 기준 목표 (수용 기준)

단계는 시스템 층이 아니라 **사용자가 겪는 순간**으로 평가한다.

| 순간 | 목표 |
| --- | --- |
| 화면을 열었다 | 3초 안에 연결 상태(끊겼다면 이유), 새 대화 수, 검토 대기 수, 마지막 정리 결과가 보인다 |
| 정리를 시작한다 | 버튼 1번. 남은 시간이 즉시 보이고 새 대화가 적으면 몇 분 안에 끝난다(전체 확인 2~3분) |
| 기다린다 | 화면을 닫아도 작업이 계속되고 다시 열면 복원된다. 429·무응답은 이유와 자동 재개 시각이 보인다 |
| 검토한다 | 전체 표 없이 요약 한 화면 + 예외 목록. 적용 전에 "무엇이 바뀌는가"를 안다 |
| 적용한다 | 버튼 1번. 내부 한도·해시·계획 파일이 보이지 않는다 |
| 끝났다 | 바뀐 것과 직접 할 일(비게 된 프로젝트 이름, 수동 제거 대화)이 결과 화면에 있다 |

## 설계 원칙

- 사용자에게 내부 한도·해시·계획 파일 이름을 노출하지 않는다. 오류는 "무슨 일이 있었고 지금 무엇을 하면 되는지"로 쓴다.
- 작업 상태는 파일이 정본이다(`runs/<id>/`, `data/jobs/*.jsonl`). 화면·서버가 죽어도 이어 간다.
- 검증은 두 층: 대화별 재조회(항상) + 전체 재수집(요청 시). 빠른 검증이 기본이다.
- 원격 변경 승인 규칙(명시 승인·확인 문구·잠금·재조회 검증)은 유지한다.
- 코드는 AI를 호출하지 않는다. 에이전트 인계는 파일 계약으로 한다.
- 안전 경계(원격 op 계약, 릴레이, 잠금, 영수증·재조회, 평평한 루트 모듈)는 겪은 문제의 원인이 아니었으므로 그대로 둔다.

## 계획과 다르게 구현한 것

- 작업 상태 영속은 `runs/<id>/job.jsonl`이 아니라 **`data/jobs/*.jsonl`**(작업 단위)이다. 서버가 죽으면 다음 조회에서 "중단됨"으로 닫는다.
- `pointer + phase`를 상태 기계로 대체하지 않았다. `GET /maintenance/session`이 포인터·작업·기준선·연결 상태를 합쳐 단계를 계산한다(`session.js`). 기준선 해시 결속은 남아 있고 후속 실행(검토 대기)이 자체 인벤토리로 우회한다.
- **증분·빠른 스캔은 만들었다가 폐기했다(2026-09-25).** 전체 대화 목록이 프로젝트 대화의 약 20%를 주지 않아 검증(probe)에 불통과했고, 전체 확인이 2~3분이라 최적화 이득도 작았다. 코드·버튼·검증 파일 계약을 모두 제거했고 확인은 항상 프로젝트를 순회하는 전체 수집이다(실측 경위는 `API_COMPATIBILITY.md`).
- 읽기 간격은 429 이력에 맞춰 조절되고, 429 쿨다운 종료 시각은 공유 pacer가 들고 있어 서버가 떠 있는 동안 다음 작업이 이어받는다(서버를 다시 켜면 초기화).
- `overhaul.js`는 일반 명령으로 흡수하지 않고 카드·조각·조립 도구로 유지한다.

## 남은 결정

- 정기 시나리오(새 대화 몇 건을 만들고 한 바퀴 정리)를 실계정에서 한 번 돌려 수용 기준을 실측한다.
- 이전 화면(`/legacy`)과 실행 포인터·`phase` 문자열을 폐기할지는 그 실측 뒤에 정한다.
- 북마클릿의 탭 가시성 보고와 프로젝트 지도 화면은 필요해질 때 만든다(북마클릿 재설치가 필요하다).
