# 릴리스 노트 작성 기준

버전 변화를 사용자에게 알리는 글의 형식과 문체를 정한다. 브랜치·커밋·릴리스 절차는 [GIT.md](GIT.md)에 있다.

## 단일 출처

`CHANGELOG.md`의 `## [Unreleased]`가 유일한 원본이다. 사용자에게 보이는 변경은 그 변경을 만드는 **같은 커밋에서** 여기에 적는다. 릴리스 때 `node src/release-notes.js release <X.Y.Z>`가 이를 버전 절로 승격하고, 같은 절이 GitHub Release 본문(`node src/release-notes.js notes <X.Y.Z>`)과 앱의 업데이트 내역이 된다. 형식은 `node src/release-notes.js check`(`npm test`와 CI에 포함)가 막는다.

## 기록하는 것과 하지 않는 것

사용자가 알아차릴 변경만 기록한다: 새 기능·설정·화면, 바뀐 동작, 겪을 수 있던 버그의 수정, 지원 환경·처리 방식의 변화, 보안 관련 사항, **북마클릿 재설치가 필요한 변경**, **`data/` 형식이 바뀌어 이전 데이터를 이어받는 방법이 필요한 변경**. 리팩터링, 테스트, 문서, CI는 기록하지 않는다(Git 이력이 소유한다).

## 절과 항목

해당하는 절만 `Added` · `Changed` · `Deprecated` · `Removed` · `Fixed` · `Security` 순서로 쓰고 빈 절은 두지 않는다. "이제 달라졌다"고 알아야 하는 의도적 변경은 `Changed`, "원래 이렇게 동작해야 했다"고 느낄 변경은 `Fixed`다.

- 형식은 `- **제목.** 설명`이다. 제목은 기능 이름, 설명은 사용자가 얻는 결과 한두 문장이며 한 항목은 200자를 넘지 않는다.
- 한 기능은 한 항목이다. 이어지는 작업은 기존 `[Unreleased]` 항목을 고친다.
- 개발자가 한 일이 아니라 사용자가 보게 될 결과를 쓴다. 커밋 제목을 옮기지 않는다.
- 합니다체로 쓰고 이모지·스크린샷·홍보 문구를 쓰지 않는다. 코드 식별자·파일명은 원문을 유지한다.
- 버전 제목 아래에 요약 문장을 쓰지 않는다. 바로 절로 시작한다.

## 버전

SemVer(`X.Y.Z`)를 따른다. `Added`가 있으면 minor 이상을 올린다(릴리스 명령이 거부한다). 북마클릿 호환 버전(`RELAY_VERSION`)은 제품 버전과 별개이며 [GIT.md](GIT.md)의 "버전과 릴리스"를 따른다.
