# ChatGPT 웹 API 호환성

앱은 로그인한 `chatgpt.com` 탭의 북마클릿으로 ChatGPT 웹의 비공식 API를 호출한다. 브라우저가 `/api/auth/session`에서 인증에 필요한 값을 읽고 원격 요청을 한 번에 하나씩 수행한다. 로컬 앱과는 `postMessage`로 고정된 `{op, params}`와 결과를 주고받는다. 계정 확인에는 계정 ID만 반환한다. 세션 응답·토큰·쿠키는 브라우저에 남는다. [인증과 원격 작업 원칙](../AGENTS.md#인증원격-호출운영)

## 요청 계약

아래 원격 경로는 `/backend-api` 기준이다. 정확한 파라미터 검증과 응답 형식은 `src/remote-ops.js`, 브라우저 요청은 [북마클릿](../public/bookmarklet.html)이 맡는다.

| 작업 | 메서드와 경로 | 사용 필드 |
| --- | --- | --- |
| 대화 목록 | `GET /conversations` | `offset`, `limit`, `is_archived`. 응답의 대화 요약, 개수, 페이지 상태를 읽는다. |
| 대화 한 건 | `GET /conversation/{conversationId}` | `conversation_id` 또는 `id`, 본문 `mapping`, `title`, 프로젝트와 표시·보관 상태를 읽는다. |
| 제목·표시 변경 | `PATCH /conversation/{conversationId}` | 요청 하나에 `title` 또는 `is_visible` 하나. 릴레이는 `is_archived`도 표현하지만 앱의 정리 흐름에서는 보관 상태를 바꾸지 않는다. |
| 소유 프로젝트 목록 | `GET /gizmos/snorlax/sidebar` | `owned_only=true`, `conversations_per_gizmo=0`, `limit`, 선택 `cursor`. 프로젝트 ID·이름·커서를 읽는다. |
| 프로젝트 대화 목록 | `GET /gizmos/{projectId}/conversations` | `limit`, 선택 `cursor`. 대화 요약과 커서를 읽는다. |
| 프로젝트 생성 | `POST /projects` | `name`, `instructions`. |
| 프로젝트 배치 | `PATCH /conversation/{conversationId}` | `gizmo_id`에 대상 프로젝트 ID. 프로젝트 간 이동도 이 요청을 쓴다. |

대화 ID는 8-4-4-4-12자리 16진수 형식으로 검증한다. 실계정 ID는 RFC 4122 버전·variant 범위를 벗어날 수 있다. 프로젝트 ID는 `g-p-`으로 시작하며, 일반 `g-` 값은 사용자 정의 GPT일 수 있다.

## 구현에 영향을 주는 관측

| 관측일 | 관측 | 구현에 반영할 점 |
| --- | --- | --- |
| 2026-09-09 | 같은 세션에서 Node는 `403` HTML, ChatGPT 페이지는 `200` JSON을 받았다. | 원격 요청은 로그인한 페이지에서 수행한다. Codex 내장 브라우저는 인증 경로에서 제외한다. |
| 2026-09-11~25 | 기존 프로젝트 사이의 이동도 반영됐다. `gizmo_id: null`은 `200`을 반환해도 프로젝트에서 대화를 빼지 못했다. | 프로젝트에서 빼야 하는 대화는 `manual-remove`로 안내한다. 변경 반영은 재조회로 확인한다. |
| 2026-09-12 | 목록과 프로젝트 경로에서 같은 대화의 `create_time`이 47초 차이 났다. | 동일성은 대화 ID로 확인한다. 변경 감지에는 `title`, `update_time`, `is_archived`, `gizmo_id`를 쓴다. |
| 2026-09-25 | 주 대화 목록에 410건 중 프로젝트 대화 84건이 빠졌다. 목록에 포함된 대화의 프로젝트 소속은 프로젝트별 목록과 일치했다. 프로젝트 없는 대화는 표본 1건이다. | 전체·특정 프로젝트 수집은 프로젝트별 목록을 읽는다. 최근·미정돈 범위에는 누락 가능성이 있고, 프로젝트 없는 대화의 목록 완전성은 추가 검증이 필요하다. |
| 2026-09-26 | 제목 변경은 `update_time`을 갱신했고, 프로젝트 이동은 기존 값을 유지했다. | 제목은 오래된 대화부터 순차 변경하고 영수증으로 바뀐 대화끼리의 상대 순서를 확인한다. |
| 날짜 미기록 | 사용자 정의 GPT 대화를 프로젝트에 배치하자 `gizmo_id`와 `conversation_template_id`가 대상 프로젝트 값으로 바뀌었다. | 기존 GPT 연결이 바뀔 수 있다. 대상 프로젝트 ID를 다시 읽어 결과를 확인한다. |
| 날짜 미기록 | 프로젝트 생성·배치에서 상태가 바뀐 뒤 `500`이 반환될 수 있다. | 자동 재시도 없이 프로젝트 목록이나 대화를 다시 읽어 승인한 상태와 대조한다. |

주 대화 목록은 수정 시각 순의 `offset` 페이지다. 대량 제목 변경 직후에는 항목이 페이지 사이로 움직일 수 있다. 결과 확인에는 변경별 재조회와 영수증을 사용한다.

## 장애 진단

| 증상 | 확인할 것 |
| --- | --- |
| 북마크를 눌러도 창이 열리지 않음 | 팝업 설정을 확인한다. 북마클릿 코드를 바꿨다면 `javascript:` URL에서 줄바꿈이 사라지는 점을 확인한다. 실행기 내부의 `//` 주석은 `inlineSource()`가 거부한다. |
| 연결됨인데 요청이 진행되지 않음 | 연결 표시는 하트비트다. 원래 ChatGPT 탭과 정리 창을 확인하고, 옛 창이 연결을 소유하는지 본다. `curl -s http://127.0.0.1:8523/relay/trace`로 멈춘 단계를 확인한다. |
| 릴레이 시간 초과 또는 `599` | `599`는 페이지 요청 예외나 기다리던 응답을 받지 못했다는 내부 상태다. 백그라운드 탭, 오래된 연결 창, 큰 본문 응답을 확인한다. `/relay/result` 한도는 64MB, 다른 경로는 2MB다. |
| 요청 제한 `429` | 읽기·쓰기가 계정 한도를 공유한다. `src/relay-api.js`의 쿨다운과 재개 기록을 확인한다. |
| 로컬 검증 오류가 반복됨 | 오류의 `retryable: false`가 유지되는지 본다. 로컬 입력 오류는 바로 드러나야 한다. |

요청이 20초 넘게 대기열에서 꺼내지지 않으면 새 창이 소유권을 인수할 수 있다. 페이지 응답 제한은 60초, 브로커 왕복 제한은 90초다. 읽기와 결과가 모호한 쓰기의 재개 조건은 [앱 동작 계약](ARCHITECTURE.md#수집정리-동작-계약)에 따른다.

## 계약이 바뀌었을 때

1. 토큰 없는 실패 기록과 영수증을 확인한다. 쓰기 결과가 불확실하면 읽기부터 수행한다.
2. 프로젝트 목록·대화 읽기로 인증, 릴레이, 원격 계약 중 어디서 실패했는지 좁힌다. 관측 기록에는 날짜·메서드·경로·최소 필드·응답과 실제 반영 여부를 남긴다.
3. 변경된 요청 계약, 브라우저 실행기, 검증 테스트와 이 문서를 함께 갱신한다. 실계정 확인은 사용자가 승인한 작은 범위에서 진행하고 결과를 다시 읽는다. [실계정 작업 권한](../AGENTS.md#작업-유형별-권한)
