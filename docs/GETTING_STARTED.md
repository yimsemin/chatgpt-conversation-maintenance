# 시작하기 — 초보자용 사용 안내

> **처음 설치·설정할 때 한 번만 읽는 문서다.** 평소 사용은 `npm run brief`의 "다음" 안내와 화면만으로 충분하다.

개발 경험이 없어도 따라 할 수 있도록 처음부터 끝까지 안내한다. 명령을 한 줄씩 그대로 입력하면 되고, 막히면 각 단계 아래의 "잘 안 될 때"를 본다.

개요와 로컬 명령은 [README.md](../README.md), 분류 판단 기준은 [CLASSIFICATION_WORKFLOW.md](../CLASSIFICATION_WORKFLOW.md)에 있다.

## 0. 이 도구가 하는 일 / 하지 않는 일

**하는 일**

- 정리할 범위(프로젝트에 넣지 않은 대화, 특정 프로젝트, 최근 며칠, 전체)를 고르면 그 범위의 대화에 대해 "어느 프로젝트에 넣을지 / 제목을 어떻게 바꿀지 / 지워도 될지"를 AI가 제안하고, 내가 화면에서 검토해 정하게 한다.
- 내가 화면에서 승인한 변경만 ChatGPT에 반영하고, 끝나면 무엇이 바뀌었는지와 내가 직접 할 일을 알려 준다.
- 지워도 될 대화는 바로 지우지 않고 **삭제후보 프로젝트**로 옮겨 두어, 내가 ChatGPT에서 직접 확인한 뒤 지우거나 되돌리게 한다.
- 제목을 `핵심 주제 — 실제 작업 또는 결과` 형식으로 통일한다.

**하지 않는 일**

- 자동으로 대화를 지우거나 옮기지 않는다. 모든 변경은 사람이 확인·승인해야 한다.
- 아카이브, ChatGPT Memory, 프로젝트 파일·지침은 건드리지 않는다(직접 관리).
- 대화 원문이나 로그인 정보를 인터넷 어딘가로 보내지 않는다. 전부 이 컴퓨터 안에서만 처리한다.

분류 제안은 대화창의 AI 에이전트(Claude Code·Codex 등)가 이 저장소의 파일을 읽고 만든다. 이 도구의 코드가 AI를 호출하지는 않는다.

## 1. 준비물

| 항목 | 설명 |
| --- | --- |
| 계정 ID가 있는 ChatGPT 워크스페이스 계정 | 이 도구는 회사·팀용 ChatGPT의 "프로젝트" 기능을 다룬다. 세션에서 계정 ID를 찾지 못하면 연결 단계에서 "account ID" 오류가 난다. 실제로 확인된 건 **Business 워크스페이스 한 곳**이고 Enterprise·Team은 확인되지 않았다. |

## 2. Node.js 설치

1. <https://nodejs.org> 에 접속한다.
2. **LTS** 버전(숫자가 24 이상)을 받아 설치 관리자를 실행하고, 기본값으로 계속 눌러 설치한다.
3. 설치가 끝나면 터미널을 연다.
   - macOS: `응용 프로그램 → 유틸리티 → 터미널`
   - Windows: 시작 메뉴에서 `PowerShell` 검색
4. 다음을 입력하고 Enter:

   ```bash
   node --version
   ```

   `v24.x.x` 처럼 24 이상이 나오면 된다.

**잘 안 될 때**

- `node: command not found` / `'node'은(는) ... 아닙니다` → 설치가 안 됐거나 터미널을 껐다 켜야 한다. 터미널을 완전히 종료 후 다시 연다.
- 버전이 24보다 낮게 나오면 nodejs.org에서 최신 LTS를 다시 설치한다.

## 3. 도구 내려받기

### 방법 A — Git 사용 (권장)

```bash
git clone https://github.com/yimsemin/chatgpt-conversation-maintenance.git
cd chatgpt-conversation-maintenance
```

### 방법 B — ZIP 다운로드 (Git이 없을 때)

1. 저장소 페이지에서 초록색 **Code** 버튼 → **Download ZIP**.
2. 받은 파일의 압축을 원하는 위치에 푼다. (예: `문서` 폴더)
3. 터미널에서 그 폴더로 이동한다. 예:

   ```bash
   cd ~/Documents/chatgpt-conversation-maintenance
   ```

> 폴더 경로를 기억해 둔다. 나중에 화면에 이 경로를 입력한다.

## 4. 첫 설정

압축을 푼(또는 clone한) 폴더 안에서 터미널에 순서대로 입력한다.

```bash
npm install
```

의존 패키지는 없지만, 이 명령이 커밋 훅 등 로컬 설정을 잡아 준다.

```bash
npm test
```

도구가 정상인지 자체 점검한다. 마지막에 `pass ...`, `fail 0`이 나오면 정상이다.

```bash
npm run repo:check
```

민감한 파일이 섞여 있지 않은지 확인한다. `Repository safety check passed`가 나오면 정상이다.

**잘 안 될 때**

- `npm: command not found` → Node.js 설치가 덜 됐다. 2단계를 다시 한다.
- `npm test`에서 `fail`이 1 이상이면 Node.js 버전이 24 미만일 가능성이 크다. `node --version`을 확인한다.

## 5. 데이터 폴더와 삭제후보 설정 (대부분 그냥 넘어가도 됨)

이 도구는 실행 결과(`runs/`: 결정·계획·영수증·결과 보고서), 작업 로그, 삭제후보로 옮긴 대화의 목록, 잠금 파일, 내가 정한 분류체계(`classification-taxonomy.md`)를 **데이터 폴더**에 저장한다. 이 폴더는 **절대 Git(공개 저장소)에 올라가지 않는다.**

내 ChatGPT 정리 기록은 **내 것이고 내 컴퓨터에만 있다.** 이 도구를 쓰는 다른 사람의 기록과 섞이지 않고, 저장소에 모이지도 않는다. 백업이 필요하면 **내가 쓰는 백업 프로그램**으로 이 폴더를 백업한다 — GitHub는 쓰지 않는다.

- 기본값은 도구 폴더 안의 `data/` 이다. **한 대에서만 쓴다면 아무것도 안 해도 된다.**
- 정리는 한 컴퓨터에서만 하는 것을 전제로 한다. 설정은 도구 폴더 안에 `.local` 폴더를 만들고 그 안에 `config.json` 파일을 만들어 적는다(이 파일은 Git에 올라가지 않는다).

  데이터 폴더 위치를 바꾸고 싶다면(예: 백업 프로그램이 감시하는 폴더에 두기):

  ```json
  { "dataDir": "/Users/내이름/Library/Mobile Documents/com~apple~CloudDocs/chatgpt-maintenance-data" }
  ```

  Windows 예:

  ```json
  { "dataDir": "C:\\Users\\내이름\\Dropbox\\chatgpt-maintenance-data" }
  ```

- **삭제 후보를 어디로 옮길지**는 `trash`로 정한다(화면에서도 바꿀 수 있고, 안 적으면 `auto`):

  | `mode` | 동작 |
  | --- | --- |
  | `auto` (기본) | 이름이 `삭제후보`인 프로젝트로 옮긴다. 없으면 새로 만든다. |
  | `fixed` | `name`으로 정한 프로젝트로 옮긴다. 그런 프로젝트가 없으면 `삭제후보` 프로젝트를 새로 만들어 옮긴다. |
  | `none` | 어디로도 옮기지 않고 삭제 후보로 표시만 한다. 이미 프로젝트 안에 있는 대화는 ChatGPT가 API로 빼는 것을 지원하지 않아 직접 빼야 한다. |

  ```json
  { "trash": { "mode": "fixed", "name": "♻️ 삭제후보" } }
  ```

  프로젝트 **이름**만 적는다(주소나 ID는 적지 않는다). 두 설정을 한 파일에 함께 적어도 된다.
- 스캔·변경은 항상 **한 번에 한 대에서만** 한다. 잠금 파일이 이를 강제한다.

## 6. 도구 켜기와 끄기

터미널에서 도구 폴더에 있는 상태로:

```bash
npm run app
```

앱의 주소는 `http://127.0.0.1:8523` 이다. 앱이 브라우저 창을 미리 열지는 않는다(정리 창은 7단계의 북마클릿이 연다).

**이 터미널 창이 앱이다.** 앱은 그 창의 프로세스로 돌고, 숨어서 돌지 않는다.

- **끄기**: 그 터미널 창을 닫거나 `Ctrl+C`를 누르면 앱이 종료된다. 브라우저 탭만 닫으면 앱은 계속 켜져 있다(작업이 도중에 끊기지 않게 하려는 것이다).
- **하나만 켜진다**: 이미 켜져 있는데 또 `npm run app`을 하면 새로 켜지 않고 "이미 실행 중입니다(프로세스 번호·시작 시각)"라고 알려 준다.
- **지금 무엇이 돌고 있는지**: 화면 위쪽에 `● 앱 실행 중 · 프로세스 번호 · 켜진 지 얼마` 줄이 항상 보인다. 터미널에서는 `npm run status`로도 확인한다.
- **터미널 창을 잃어버렸을 때**: `npm run stop`으로 끈다(화면 고급의 **앱 종료** 버튼도 같다). 진행 중인 작업이 있으면 끝나거나 중단된 뒤에 종료된다.
- **코드를 바꾼 뒤**: 앱이 켜진 뒤 코드가 바뀌면 화면 위쪽 줄이 "새 코드를 쓰려면 다시 켜세요"라고 알린다. `Ctrl+C`로 끄고 다시 켠다.
- macOS는 폴더의 `start-local.command`, Windows는 `start-local.cmd` 파일을 더블클릭해도 된다. 열린 창이 앱이며(이 창을 닫으면 앱이 꺼진다), 어느 폴더에서 켜든 앱은 이 저장소 폴더를 작업 폴더로 쓴다.
- 이 서버는 **내 컴퓨터에서만** 동작한다. 인터넷에 공개되지 않는다. 컴퓨터를 재부팅했으면 다시 켠다.

**잘 안 될 때**

- "이미 대화 정리 앱이 실행 중입니다" → 그 앱을 켠 터미널 창에서 `Ctrl+C`로 끄거나 `npm run stop`을 실행한 뒤 다시 켠다. 예전 버전 앱이 남아 있다면(화면에 위쪽 줄이 없거나 `npm run stop`이 통하지 않는 경우) 터미널에서 `npm run status`로 프로세스 번호를 확인해 `kill <번호>`로 끈다(Windows는 작업 관리자에서 `node` 프로세스 종료).
- 화면에 "앱 서버에 연결하지 못했습니다"가 보이면 앱이 꺼진 것이다. 터미널에서 `npm run app`을 다시 실행한다.

## 7. ChatGPT 연결 (북마클릿)

앱을 켜면 터미널에 "다음: chatgpt.com 에서 북마클릿을 누르세요"라고 나온다. 이 단계에서는 ChatGPT가 바뀌지 않는다. **정리 작업은 북마클릿이 여는 '대화 정리' 창 하나에서 한다**(별도로 앱 주소를 열 필요가 없다. 처음 쓸 때만 앱이 북마클릿 설치 안내를 브라우저에 열어 준다).

1. 안내 페이지(`http://127.0.0.1:8523/auth/bookmarklet`, 또는 화면 고급의 **"ChatGPT 연결 방법"**)의 **"ChatGPT → 유지관리"** 버튼을 브라우저 **북마크바로 드래그**해 등록한다(한 번만).
2. `chatgpt.com` 에 로그인한 탭을 열고, 방금 만든 북마크를 클릭한다.
3. **'대화 정리' 창**이 열리고 오른쪽 위가 **"ChatGPT 연결됨"** 으로 바뀌면 성공이다. 이 창이 정리 화면이면서 ChatGPT와의 연결도 맡는다. **정리가 끝날 때까지 이 창과 chatgpt.com 탭을 닫거나 최소화하지 않는다**(chatgpt.com 탭은 앞에 두는 편이 안정적이다). 창을 잘못 닫았으면 chatgpt.com에서 북마크를 다시 누른다.

앱 주소(`http://127.0.0.1:8523`)를 일반 탭으로 열어도 화면은 보이고 작업도 시작할 수 있지만, 연결은 북마클릿으로 연 정리 창이 맡고 있어야 한다. 그러니 창을 하나로 쓰는 편이 헷갈리지 않는다.

**잘 안 될 때**

- "account ID" 관련 오류 → 세션 토큰에서 ChatGPT 계정 ID를 찾지 못한 것이다. 개인(Plus/Free) 계정일 가능성이 크다. 실제로 확인된 동작 범위는 Business 워크스페이스 하나뿐이며 Enterprise·Team은 확인되지 않았다([README.md](../README.md)의 "빠른 시작").
- 북마크를 눌러도 반응이 없음 → 팝업이 차단됐다. 주소창의 팝업 차단 아이콘에서 이 사이트 팝업을 허용한다.
- "연결 끊김"으로 바뀜 → chatgpt.com 탭이나 정리 창이 닫혔거나 탭이 백그라운드에서 멈췄다. chatgpt.com 탭을 앞으로 가져오고, 안 되면 북마크를 다시 누른다.
- "북마클릿 업데이트 필요" → chatgpt.com의 북마클릿이 앱보다 오래됐다. 북마클릿을 다시 설치한 뒤 누른다.

## 8. 대화 확인 (조사 범위 고르기)

화면 위쪽 카드에서 **조사 범위**를 고르고 **"이 범위 확인"** 을 누른다.

| 조사 범위 | 언제 쓰나 |
| --- | --- |
| 프로젝트에 넣지 않은 대화 (기본) | 프로젝트로 정돈하는 것이 이 도구의 핵심 용도다 |
| 특정 프로젝트의 대화 | 작업을 마무리한 프로젝트를 정돈할 때. 다른 프로젝트는 읽지 않는다. 프로젝트를 **여러 개** 고를 수 있다. 처음에는 "프로젝트 목록 읽기"(몇 초)를 눌러 프로젝트를 불러오며, 저장해 두고 최근에 쓴 프로젝트가 앞에 보인다 |
| 최근 며칠 안에 수정한 대화 | 최근에 쌓인 것만 볼 때. 프로젝트 안의 대화는 ChatGPT 목록에서 일부 빠질 수 있으니 빠짐없이 보려면 프로젝트 범위를 쓴다 |
| 모든 대화 | 처음부터 다시 정리할 때. 본문을 전부 받아 수 분~수 시간 걸리고 끊기면 이어받는다 |

- ChatGPT를 **바꾸지 않는다.** 읽기만 한다. 걸리는 시간은 대부분 후보 대화의 본문을 받는 데 쓰이며(대화 한 건에 몇 초) 후보 수에 비례한다. 프로젝트 범위는 목록 전체를 읽지 않는다.
- 진행률과 남은 시간이 보인다. 화면을 닫아도 서버가 계속하고, 다시 열면 이어서 보인다.
- 끝나면 그 범위의 대화가 "후보"로 잡힌다. 후보가 없으면 "이 범위에는 정리할 대화가 없습니다"가 나온다.
- 분류·검토를 기다리는 정리가 있는데 다른 범위를 보고 싶으면 위쪽 **범위 다시 고르기**를 누른다. 새 확인을 시작하기 전에는 아무것도 버려지지 않고, 시작하면 기존 정리는 버려진다(ChatGPT는 바뀌지 않는다).
- 앱을 새 버전으로 바꾼 뒤에는 **앱을 다시 켠다**(6단계: `Ctrl+C` 후 `npm run app`). 예전 버전으로 시작한 정리는 쓸 수 없어 화면이 버렸다고 알려 준다.
- 노란색 429·재시도 안내는 ChatGPT가 잠시 요청을 제한한 것이다. 도구가 알아서 기다렸다 다시 시도하니 그대로 둔다.

**잘 안 될 때**

- 화면 맨 위에 빨간 안내가 뜨면 거기 적힌 "무엇을 하면 되는지"를 따른다. 자세한 내용이 필요하면 **오류 복사**를 눌러 에이전트에게 붙여넣는다.
- "작업 폴더를 확인하세요" → 고급 메뉴의 작업 폴더가 이 도구 폴더가 맞는지 확인한다.

## 9. 분류 제안 → 검토 → 적용

**제안.** 후보가 생기면 화면이 에이전트에게 전달할 한 문장을 보여 준다. 이 저장소를 열어 둔 AI 에이전트(Claude Code·Codex 등)에게 그대로 전달하면 분류 제안 파일이 만들어지고, 화면이 저절로 다음 단계로 넘어간다. 에이전트가 없으면 "에이전트 없이 결과 JSON을 붙여넣기"를 쓴다.

**검토.** 화면이 "삭제후보로 이동 2건 · 프로젝트 이동 4건 · 제목 변경 2건 · 새 프로젝트 1개" 같은 요약과 프로젝트별 증감을 먼저 보여 준다. 그 아래에서 필요한 것만 펼쳐 고친다.

| 항목 | 할 수 있는 것 |
| --- | --- |
| 삭제 후보 처리 방식 | 삭제후보 프로젝트로 옮기기(기본, 이름 바꾸기 가능) · 옮기지 않고 표시만 하기 · (고급) 영구 삭제 |
| 삭제후보로 옮길 대화 | 표준 제목 확인·수정(삭제후보로 옮길 때도 표준 제목이 필요하다) |
| 미결정 | 보존 또는 삭제 선택(정해야 적용할 수 있다) |
| 프로젝트 이동 | 이동할 프로젝트를 바꾸거나 "프로젝트 없음" 선택 |
| 제목 변경 | 새 제목 수정(`주제 — 실제 작업 또는 결과` 형식이 아니면 표시되고 적용이 막힌다) |

- 프로젝트는 선택이다. 맞는 곳이 없으면 프로젝트 없음이 정상이다. 이미 프로젝트 안에 있는 대화를 프로젝트 없음으로 옮기는 것은 앱이 할 수 없어서, 결과 화면이 "직접 하실 일"로 알려 준다.
- 검토 화면에서 고른 삭제후보 프로젝트가 ChatGPT에 없으면 적용할 때 새로 만든다.

**적용.** 아래 **"적용"** 버튼을 누르고 확인 창에서 시작한다.

- 영구 삭제가 있으면 "되돌릴 수 없음을 확인했습니다"에 체크해야 시작된다.
- 시작하면 끝날 때까지 자동으로 이어진다. 제목 변경은 수정 시각이 오래된 대화부터 한 번에 하나씩 한다(바꾼 대화끼리 목록 순서를 지키려는 것이다). 429나 페이지 응답 지연은 기다렸다가 다시 시도하고, 중단 버튼으로 멈출 수 있다. 창을 닫아도 서버가 계속한다.
- 변경은 적용하면서 대화마다 다시 읽어 확인하고 그 기록(영수증)이 실행 폴더에 남는다.

**결과.** 무엇이 바뀌었는지, 프로젝트별 이전·이후, 제목을 바꾼 대화의 목록 순서 확인, 그리고 **직접 하실 일**(비게 된 프로젝트 이름, 프로젝트에서 직접 빼야 하는 대화, 삭제 표시만 한 대화)이 나온다. 같은 내용이 `data/runs/<실행>/report.md`에도 저장된다. 특정 프로젝트·표본 범위처럼 일부만 읽은 경우 읽지 않은 프로젝트의 대화 수는 "—"로 나온다.

## 10. 삭제후보 확정

삭제후보 프로젝트로 옮겨 둔 대화가 있으면 첫 화면에 "삭제후보 N건"(가장 오래된 것이 며칠 전인지 포함)이 보인다. ChatGPT의 그 프로젝트에서 대화를 직접 확인한 뒤 **삭제후보 확인**에서 대화마다 삭제 또는 원래 자리(프로젝트 선택)로 정하고 "확정하고 적용"을 누른다. 적용 방식은 위와 같다.

ChatGPT에서 직접 지우거나 다른 곳으로 옮긴 대화가 있으면 **ChatGPT에서 다시 확인**(읽기 전용)을 눌러 목록에서 뺀다. 지웠다면 그냥 ChatGPT에서 지워도 되고, 이 도구의 목록은 그 확인으로 맞춰진다.

## 11. 자주 묻는 질문

**Q. 매번 무엇부터 하나요?**
도구 폴더에서 `npm run app` → chatgpt.com에서 북마클릿 실행(연결) → 조사 범위 선택 후 "이 범위 확인" → 분류 제안 → 검토 → 적용.

**Q. 실수로 삭제하면요?**
삭제는 되돌릴 수 없다. 그래서 기본은 삭제후보 프로젝트로 옮기는 것이고, 영구 삭제는 고급 옵션이며 확인 창에서 한 번 더 확인한다.

**Q. 이전 상태를 기록해 두는 파일이 있나요?**
없다. 지난 목록과 지금을 비교하는 방식이 아니라, 고른 범위를 그때그때 읽는다. 무엇을 했는지는 `data/runs/<실행>/`의 결정·계획·영수증·`report.md`와 `data/jobs/`의 작업 로그에 남는다.

**Q. `data/` 폴더를 실수로 공개 저장소에 올릴까 걱정됩니다.**
`.gitignore`가 `data/`를 제외하고, `npm run repo:check`가 한 번 더 막는다. 커밋 전에 이 명령을 습관적으로 실행한다.

**Q. 컴퓨터를 바꾸거나 백업하려면요?**
5단계처럼 데이터 폴더를 내 백업 프로그램이 다루는 위치로 지정하면 된다. 정리 작업 자체는 한 컴퓨터에서만 한다. 새 컴퓨터에서는 거기서 새로 확인해서 시작하면 된다. 자세한 건 [README.md](../README.md)의 "데이터와 백업".

**Q. API가 갑자기 안 돼요.**
ChatGPT 내부 API가 바뀐 것일 수 있다. [API_COMPATIBILITY.md](../API_COMPATIBILITY.md)의 대조 순서를 따른다. 대량 재시도는 하지 않는다.

## 12. 안전 요약

- 세션·토큰·쿠키는 ChatGPT 페이지 밖으로 나오지 않고 파일·로그에 남지 않는다. 대화 원문은 데이터 폴더에만 저장된다.
- **예외:** 선택 경로인 외부 AI 분류를 쓰면 후보 대화의 발췌본(제목, 프로젝트명, 요청·응답의 앞뒤 일부)을 사용자가 직접 복사해 그 AI 서비스에 붙여넣게 된다. 이건 그 서비스로 나가는 데이터다. 화면에서 직접 결정하면 나가지 않는다.
- `data/`, `.local/`, 세션·쿠키 파일은 절대 커밋하지 않는다. 프로젝트 주소·ID도 설정·문서에 적지 않는다.
- 모든 ChatGPT 변경은 사람이 화면에서 승인한 것만 실행된다.
- 이 도구는 비공식 API를 쓰므로 계정 약관 확인은 사용자 책임이다.
