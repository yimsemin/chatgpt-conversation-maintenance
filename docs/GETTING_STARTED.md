# 시작하기 — 초보자용 사용 안내

이 문서는 개발 경험이 없어도 따라 할 수 있도록 처음부터 끝까지 안내한다. 명령을 한 줄씩 그대로 입력하면 된다. 막히면 각 단계 아래의 "잘 안 될 때"를 본다.

수동 CLI 절차와 내부 동작은 [README.md](../README.md), 분류 판단 기준은 [CLASSIFICATION_WORKFLOW.md](../CLASSIFICATION_WORKFLOW.md)에 있다.

## 0. 이 도구가 하는 일 / 하지 않는 일

**하는 일**

- 내 ChatGPT 대화 목록을 컴퓨터 화면에서 보여준다.
- 새로 생기거나 바뀐 대화만 골라 "삭제할지 / 제목을 바꿀지 / 어느 프로젝트에 넣을지"를 내가 직접 정하게 한다.
- 내가 화면에서 승인한 변경만 ChatGPT에 반영한다.

**하지 않는 일**

- 자동으로 대화를 지우거나 옮기지 않는다. 모든 변경은 사람이 확인·승인해야 한다.
- 아카이브, ChatGPT Memory, 프로젝트 파일·지침은 건드리지 않는다(직접 관리).
- 대화 원문이나 로그인 정보를 인터넷 어딘가로 보내지 않는다. 전부 이 컴퓨터 안에서만 처리한다.

AI 분류는 **선택 사항**이다. 후보가 적으면 화면에서 직접 정하면 되고, AI는 없어도 된다.

## 1. 준비물

| 항목 | 설명 |
| --- | --- |
| 계정 ID가 있는 ChatGPT 워크스페이스 계정 | 이 도구는 회사·팀용 ChatGPT의 "프로젝트" 기능을 다룬다. 세션에서 계정 ID를 찾지 못하면 연결 단계에서 "account ID" 오류가 난다. 실제로 확인된 건 **Business 워크스페이스 한 곳**이고 Enterprise·Team은 확인되지 않았다. |
| 이미 만들어진 기준선(`state.json`) | 이 도구는 기존 기준선을 증분 갱신만 한다. 데이터 폴더에 `state.json`이 없으면 시작할 수 없고, 기준선을 처음 만드는 기능은 아직 없다. |
| Node.js 24 이상 | 도구를 실행하는 런타임. 아래 2단계에서 설치한다. |
| macOS 또는 Windows | 둘 다 지원한다. |
| 웹 브라우저 | Chrome, Edge, Safari 등. 북마크바를 쓸 수 있어야 편하다. |

이 도구는 OpenAI의 공식 제품이 아니고, ChatGPT 웹 앱의 **문서화되지 않은 내부 API**를 사용한다. 예고 없이 동작이 바뀔 수 있으며, 내 계정 약관을 확인할 책임은 사용자에게 있다. 자세한 내용은 [README.md](../README.md)의 "중요한 전제: 비공식 API"를 본다.

## 2. Node.js 설치

1. <https://nodejs.org> 에 접속한다.
2. **LTS** 버전(숫자가 24 이상)을 받아 설치 관리자를 실행하고, 기본값으로 계속 눌러 설치한다.
3. 설치가 끝나면 터미널을 연다.
   - macOS: `응용 프로그램 → 유틸리티 → 터미널`
   - Windows: 시작 메뉴에서 `PowerShell` 검색
4. 다음을 입력하고 Enter:

   ```bash
   node --version
   ```

   `v24.x.x` 처럼 24 이상이 나오면 된다.

**잘 안 될 때**

- `node: command not found` / `'node'은(는) ... 아닙니다` → 설치가 안 됐거나 터미널을 껐다 켜야 한다. 터미널을 완전히 종료 후 다시 연다.
- 버전이 24보다 낮게 나오면 nodejs.org에서 최신 LTS를 다시 설치한다.

## 3. 도구 내려받기

### 방법 A — Git 사용 (권장)

```bash
git clone https://github.com/yimsemin/chatgpt-conversation-maintenance.git
cd chatgpt-conversation-maintenance
```

### 방법 B — ZIP 다운로드 (Git이 없을 때)

1. 저장소 페이지에서 초록색 **Code** 버튼 → **Download ZIP**.
2. 받은 파일의 압축을 원하는 위치에 푼다. (예: `문서` 폴더)
3. 터미널에서 그 폴더로 이동한다. 예:

   ```bash
   cd ~/Documents/chatgpt-conversation-maintenance
   ```

> 폴더 경로를 기억해 둔다. 나중에 화면에 이 경로를 입력한다.

## 4. 첫 설정

압축을 푼(또는 clone한) 폴더 안에서 터미널에 순서대로 입력한다.

```bash
npm install
```

의존 패키지는 없지만, 이 명령이 커밋 훅 등 로컬 설정을 잡아 준다.

```bash
npm test
```

도구가 정상인지 자체 점검한다. 마지막에 `pass ...`, `fail 0`이 나오면 정상이다.

```bash
npm run repo:check
```

민감한 파일이 섞여 있지 않은지 확인한다. `Repository safety check passed`가 나오면 정상이다.

**잘 안 될 때**

- `npm: command not found` → Node.js 설치가 덜 됐다. 2단계를 다시 한다.
- `npm test`에서 `fail`이 1 이상이면 Node.js 버전이 24 미만일 가능성이 크다. `node --version`을 확인한다.

## 5. 데이터 폴더 정하기 (대부분 그냥 넘어가도 됨)

이 도구는 내 대화 목록의 기준선(`state.json`), 실행 기록, 잠금 파일, 내가 정한 분류체계(`classification-taxonomy.md`)를 **데이터 폴더**에 저장한다. 이 폴더는 **절대 Git(공개 저장소)에 올라가지 않는다.**

내 ChatGPT 정리 기록은 **내 것이고 내 컴퓨터에만 있다.** 이 도구를 쓰는 다른 사람의 기록과 섞이지 않고, 저장소에 모이지도 않는다. 백업이 필요하면 **내가 쓰는 백업 프로그램**으로 이 폴더를 백업한다 — GitHub는 쓰지 않는다.

- 기본값은 도구 폴더 안의 `data/` 이다. **한 대에서만 쓴다면 아무것도 안 해도 된다.**
- 정리는 한 컴퓨터에서만 하는 것을 전제로 한다. 데이터 폴더 위치를 바꾸고 싶다면(예: 백업 프로그램이 감시하는 폴더에 두기) 도구 폴더 안에 `.local` 폴더를 만들고 그 안에 `config.json` 파일을 아래처럼 만든다:

  ```json
  { "dataDir": "/Users/내이름/Library/Mobile Documents/com~apple~CloudDocs/chatgpt-maintenance-data" }
  ```

  Windows 예:

  ```json
  { "dataDir": "C:\\Users\\내이름\\Dropbox\\chatgpt-maintenance-data" }
  ```

- 스캔·변경은 항상 **한 번에 한 대에서만** 한다. 잠금 파일이 이를 강제한다.

## 6. 도구 켜기

터미널에서 도구 폴더에 있는 상태로:

```bash
npm run app
```

잠시 뒤 브라우저에 **유지관리 화면**이 열린다. 주소는 `http://127.0.0.1:8523` 이다.

- macOS는 폴더의 `start-local.command`, Windows는 `start-local.cmd` 파일을 더블클릭해도 된다.
- 이 서버는 **내 컴퓨터에서만** 동작한다. 인터넷에 공개되지 않는다.
- 컴퓨터를 재부팅했으면 다시 `npm run app`(또는 더블클릭)을 실행한다.
- 창을 닫아도 서버는 백그라운드에 잠깐 남는다. 완전히 끄려면 터미널에서 `Ctrl+C`.

**잘 안 될 때**

- `Port 8523 is already in use` → 도구가 이미 켜져 있다. 브라우저에서 `http://127.0.0.1:8523` 을 직접 연다.
- 브라우저가 자동으로 안 열리면 주소창에 `http://127.0.0.1:8523` 을 직접 입력한다.

## 7. ChatGPT 릴레이 연결

화면 **1번 카드(릴레이와 작업 폴더)** 에서 한다. 세션은 ChatGPT 페이지에만 남고 로컬 앱으로 전달되지 않는다.

### 방법 A — 북마클릿 (권장, 복사·붙여넣기 없음)

1. 1번 카드의 **"북마클릿 설정"** 링크를 클릭한다.
2. 안내 페이지의 **"ChatGPT → 유지관리"** 버튼을 브라우저 **북마크바로 드래그**해 등록한다.
3. `chatgpt.com` 에 로그인한 탭을 연다.
4. 방금 만든 북마크를 클릭한다. 유지관리 앱 창이 열리면 성공이다.
5. 상단 **"ChatGPT 릴레이"** 상태가 **"연결됨"** 으로 바뀌는지 확인하고, 작업이 끝날 때까지 두 창을 열어 둔다.

**잘 안 될 때**

- "account ID" 관련 오류 → 세션 토큰에서 ChatGPT 계정 ID를 찾지 못한 것이다. 개인(Plus/Free) 계정일 가능성이 크다. 실제로 확인된 동작 범위는 Business 워크스페이스 하나뿐이며 Enterprise·Team은 확인되지 않았다([README.md](../README.md)의 "요구 사항과 최초 확인").
- 북마크를 눌러도 반응이 없음 → 팝업이 차단됐다. 주소창의 팝업 차단 아이콘에서 이 사이트 팝업을 허용한다.
- "연결 대기"로 바뀜 → 원래 ChatGPT 탭 또는 앱 창 연결이 끊겼다. chatgpt.com에서 북마크를 다시 누른다.

## 8. 새 대화 확인 (스캔)

1. 1번 카드의 **"유지관리 프로젝트 폴더"** 입력창에 3단계에서 기억해 둔 **도구 폴더 경로**를 넣는다.
2. **"새 대화 확인"** 버튼을 누른다.
3. 4번 카드의 진행 로그가 움직이고, 끝나면 2번 목록과 3번 표가 채워진다.

- 스캔은 **ChatGPT를 전혀 바꾸지 않는다.** 목록만 읽는다.
- 스캔은 데이터 폴더의 기존 기준선(`state.json`)과 현재 ChatGPT 목록을 비교해 새로 생기거나 바뀐 대화만 "후보"로 잡는다. 기준선 파일이 없으면 스캔은 시작되지 않는다(기준선을 처음 만드는 기능은 아직 없다).
- 2번 카드에서 제목 검색, 프로젝트 필터, 정렬을 할 수 있다.

**잘 안 될 때**

- "데이터 폴더에 state.json이 없습니다" → 아직 기준선이 없다. 현재 버전으로는 여기서 더 진행할 수 없다.
- "폴더 확인 필요" → 경로가 틀렸다. 터미널에서 `pwd`(macOS) 또는 `cd`(Windows) 결과를 그대로 붙여넣는다.
- 노란색 `[rate-limit]` 로그 → ChatGPT가 잠시 요청을 제한한 것이다. 도구가 알아서 기다렸다 다시 시도한다. 그대로 둔다.

## 9. 검토 · 결정 · 적용

3번 카드 **(검토 · 결정 · 적용)** 의 표에서 후보마다 정한다.

| 열 | 정하는 것 |
| --- | --- |
| 결정 | **보존** 또는 **삭제** |
| 새 제목 | 보존이면 `주제 — 실제 작업 또는 결과` 형식으로. 예: `분기 매출 보고 — 자동 집계 스프레드시트 설계` |
| 프로젝트 | 이 대화를 넣을 프로젝트. 목록에 없는 이름을 쓰면 새 프로젝트로 만든다. |

규칙:

- 제목이 `A — B` 형식이 아니면 아래에 빨간 힌트가 뜨고 적용이 막힌다.
- 이미 다른 프로젝트에 들어 있는 대화는 이 화면에서 옮길 수 없다. ChatGPT에서 직접 옮긴 뒤 다시 스캔한다.
- 보존 대화에는 프로젝트가 반드시 있어야 한다.

정했으면 맨 아래 **"결정 저장 및 적용"** 을 누른다.

- 삭제가 포함돼 있으면 "N개 대화를 삭제합니다. 적용할까요?" 확인창이 뜬다.
- 적용이 끝나면 도구가 ChatGPT의 실제 상태를 다시 확인하고 기준선(`state.json`)을 갱신한다.
- 별도의 커밋·업로드 단계는 없다.

## 10. (선택) AI에게 분류 맡기기

후보가 많아 하나씩 정하기 번거로울 때만 쓴다.

1. 3번 카드에서 **"AI 분류 요청문 복사"** 또는 **"Claude 요청문 복사 (자립형)"** 를 누른다.
2. 복사된 요청문을 외부 AI 채팅(ChatGPT, Claude 등)에 붙여넣는다.
3. AI가 만들어 준 `proposal.json` 전체를 3번 카드의 **"AI 분류 결과(JSON) 붙여넣기"** 칸에 넣고 **"검증하고 아래 표 채우기"** 를 누른다.
4. 표가 채워지면 사람이 다시 검토한 뒤 9단계처럼 적용한다.

권장: 먼저 저비용 모델로 전체를 훑고, 삭제·새 프로젝트·애매한 항목만 더 강한 모델로 재검토한다.

## 11. 자주 묻는 질문

**Q. 매번 무엇부터 하나요?**
도구 폴더에서 `npm run app` → chatgpt.com에서 북마클릿 실행 → "새 대화 확인" → 검토·결정·적용.

**Q. 세션이 유출되지 않나요?**
세션 토큰과 쿠키는 ChatGPT 페이지 밖으로 보내지 않는다. 앱·디스크·로그에는 남지 않으며 두 창 중 하나를 닫으면 릴레이가 끊긴다.

**Q. 실수로 삭제하면요?**
적용 전에 항상 확인창이 있고, 삭제는 후보로 잡힌 대화에 한정된다. 그래도 되돌리기 어려우므로 삭제 결정은 신중히 한다.

**Q. `data/` 폴더를 실수로 공개 저장소에 올릴까 걱정됩니다.**
`.gitignore`가 `data/`를 제외하고, `npm run repo:check`가 한 번 더 막는다. 커밋 전에 이 명령을 습관적으로 실행한다.

**Q. 컴퓨터를 바꾸거나 백업하려면요?**
5단계처럼 데이터 폴더를 내 백업 프로그램이 다루는 위치로 지정하면 된다. 정리 작업 자체는 한 컴퓨터에서만 한다. 새 컴퓨터에서 이어가게 되면 거기서 다시 스캔해서 시작한다. 자세한 건 [README.md](../README.md)의 "데이터 보관과 백업".

**Q. 내 대화 제목이나 프로젝트명이 저장소에 올라가나요?**
아니다. 기준선·실행 기록·분류체계는 전부 데이터 폴더에만 있고 `.gitignore`와 `npm run repo:check`가 막는다. 저장소에 올라가는 건 코드·테스트·문서뿐이다.

**Q. API가 갑자기 안 돼요.**
ChatGPT 내부 API가 바뀐 것일 수 있다. [API_COMPATIBILITY.md](../API_COMPATIBILITY.md)의 대조 순서를 따른다. 대량 재시도는 하지 않는다.

## 12. 안전 요약

- 세션·토큰·쿠키는 ChatGPT 페이지 밖으로 나오지 않고 파일·로그에 남지 않는다. 대화 원문은 데이터 폴더에만 저장된다.
- **예외:** 선택 경로인 외부 AI 분류를 쓰면 후보 대화의 발췌본(제목, 프로젝트명, 요청·응답의 앞뒤 일부)을 사용자가 직접 복사해 그 AI 서비스에 붙여넣게 된다. 이건 그 서비스로 나가는 데이터다. 화면에서 직접 결정하면 나가지 않는다.
- `data/`, `.local/`, 세션·쿠키 파일은 절대 커밋하지 않는다.
- 모든 ChatGPT 변경은 사람이 화면에서 승인한 것만 실행된다.
- 이 도구는 비공식 API를 쓰므로 계정 약관 확인은 사용자 책임이다.
