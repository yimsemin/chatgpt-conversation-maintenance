# 릴레이에서 반복해서 깨진 것들

릴레이·북마클릿·재시도·`server.js`를 고치기 전에만 읽는다. 진단에 가장 오래 걸린 항목이라 같은 함정을 다시 밟지 않도록 남긴다.

- **북마클릿 executor 안에 `//` 라인 주석을 두지 않는다.** `javascript:` URL은 저장·실행 과정에서 줄바꿈이 사라져 `//` 뒤 코드가 함수 끝까지 주석이 되고, 북마클릿이 통째로 죽는다(클릭해도 창이 열리지 않는다). 생성기 `inlineSource()`가 거부하고 테스트가 막지만, 설명은 executor 밖에 쓰거나 `/* */`를 쓴다.
- **로컬 검증 실패를 재시도 경로에 넣지 않는다.** `error.retryable = false`를 빼면 HTTP 상태 없는 `[retry]`가 지수 백오프로 반복되다 약 15분 뒤 실패한다. 화면에 원인이 전혀 드러나지 않는다.
- **식별자 정규식을 실측 없이 조이지 않는다.** 실제 ChatGPT 대화 ID는 RFC 4122 버전·variant 범위 밖이다(버전 니블 8 관측). 8-4-4-4-12 16진수까지만 강제한다. 경로 주입 차단에는 그것으로 충분하다.
- **릴레이 결과에는 대화 본문 전체가 실린다.** `/relay/result`만 64MB 한도를 쓴다(`bodyLimitForPath`). 다른 경로는 2MB. 한도가 모자라면 결과가 브로커에 닿지 못해 엉뚱하게 "relay timed out"으로 실패한다.
- **유지관리 창은 한 번에 하나만 연다.** 먼저 연결한 창이 릴레이를 소유하고 새 창은 거절된다. 빼앗게 두면 밀려난 창이 페이지 하트비트로 루프를 재시작해 양쪽이 서로를 무한히 밀어낸다.
- **화면의 `연결됨`은 원격 요청 성공을 뜻하지 않는다.** 하트비트만 확인한 상태다. 실패 위치는 `curl -s http://127.0.0.1:8523/relay/trace`로 본다(단계·op·요청 ID 앞 8자·HTTP 상태·경과 시간만 남는다).
- **변경 응답 200만으로 성공 처리하지 않는다.** `gizmo_id: null` PATCH는 200을 반환하고도 반영되지 않았다. 쓰기 뒤 재조회 검증을 유지한다.
- 429는 `relay-api.js`의 쿨다운·백오프로만 처리한다. 별도 대량 재시도를 추가하지 않는다.
